# 0009 — ALP-OS Live scope and simplifications (owner, 2026-10-18)

- **Status:** accepted (owner decisions; `decisions.md` 2026-10-18)
- **Supersedes:** ADR 0006 "Live never writes to internal disks"; ADR 0005
  2 GB system image limit (for Live); parts of `docs/plans/live-*.md`

## Decisions

1. Live does everything the installer will (hardware check, network, disk
   choice, encrypted archive, phone backup with Immich, QR chain), alpha or
   beta quality, with a polished graphical UI (Apple setup-assistant style,
   2016–2018). Live is for field tests and to establish the installer.
2. Live may **write files** to disks already in the computer (one folder
   `ALPArchive` on a partition the user picks) but **never deletes or
   formats** anything. Disk management comes only with the installer.
3. System image limit for Live: **4 GB** (4,000,000,000 bytes). The root
   EROFS is zstd-compressed (`Compression=zstd`, systemd-repart ≥ 257;
   kernel `CONFIG_EROFS_FS_ZIP_ZSTD=y`).
4. BitLocker computers are out of scope for now; Secure Boot off.
5. Security on Live: a simple password for the Linux admin user, local
   console only (no network login). The archive stays encrypted (LUKS2) with
   its key file on the stick; no TPM sealing and no recovery words on Live.
6. The seed (words/QR) belongs only to the sync chain the user joins, like
   Brave Sync; it is not a disk recovery key.
