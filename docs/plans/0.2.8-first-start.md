# 0.2.8 — First start of the installed system (plan)

Status: plan, 2026-11-25. Follows `0.2.8-installer.md` (the installer is
done: T-INST-01 installs, the disk starts alone and finds the seed).
Contracts: `firstboot-seed.md`, `disk-layout.md`. ADRs 0009, 0011, 0013,
0014, 0028.

## Goal

On the first start of an installed disk the screen walks the same setup as
Live (network, password, recovery code, phone), minus "where": the archive
goes onto the `alp-data` partitions the user confirmed in the installer
(the seed). One data disk: Btrfs `dup`. Two or more: `RAID1`. Encrypted
always. Nothing outside the seed's members is touched.

## What is reused (no new cryptography)

- **The index** (ADR 0011, `alp_live::index`): LUKS2 with the user's
  password (cryptsetup defaults, argon2id), TPM2 auto-unlock slot (ADR 0012),
  holds the random archive key file and the other secrets. On the installed
  system it is a partition on the system disk instead of the stick.
- **Recovery code** (ADR 0013): `recovery::bind(secret)` adds a LUKS key
  slot made from the 15 words to every pool member.
- **Live's open/lock flow**, screens and API: unchanged names; the installed
  system reports one more archive kind.

## What is new

1. **Layout (contract change, `disk-layout.md`):** a 1 GiB `alp-index`
   partition after `alp-state` on the system disk (type
   `A3E1C6B2-5B7E-4F0A-9C1D-6B2F0E8A4D11`, the index's own), created empty
   by the installer, formatted LUKS2 at the password step. Kept small: the
   index holds secrets and settings only. Immich's database and thumbnails
   move into the pool (`@immich` subvolume), because on tens of TB the
   thumbnails alone outgrow any fixed partition.
2. **Pool creation** (`alp-storage`, block 4, replaces the stub
   `create_pool`), run by `alpd` once the index is open:
   - Check the seed (contract rules 1–3): members rediscovered by partition
     UUID, serial and size match, `alp_hw::safety::check_member` passes,
     plan digest recomputed and equal. Any mismatch: `ALP-INST-005`, nothing
     written.
   - Per member: `cryptsetup luksFormat --type luks2` with the index key
     file (stdin/file, never argv), `cryptsetup open` as `alp-pool-<n>`.
   - `mkfs.btrfs -L alp-pool -d dup -m dup` (one member) or
     `-d raid1 -m raid1` (two or more); subvolumes `@archive`, `@immich`,
     `@snapshots`; mounted at `POOL_MNT`, `@archive` at `FILES_MNT`.
   - Each step is idempotent and resumable: a restart in the middle finds
     what exists (LUKS header with our label, Btrfs with label `alp-pool`)
     and continues. The seed is deleted last (contract rule 4).
3. **Open at start:** `alp-live-archive.service` opens every member with the
   key file from the index, then `btrfs device scan` and mount. A missing
   member of a RAID1 pool: mount `degraded` read-only and the home screen
   says which disk is missing (alert level from ADR 0023); never `degraded`
   read-write by itself.
4. **Setup steps on the installed system:** `where` is left out (the seed
   decided it); `password` makes the index, then pool creation runs with a
   progress bar; `recovery` binds the code to every member.

## Tests

- Unit: seed checks (each refusal), command lists for 1 and 2 members,
  resume after each step, degraded rules.
- VM `T-INST-02` (installed group): install on two 64 GB disks, first start,
  set a password through the API, pool created as RAID1 (`btrfs filesystem
  df` shows RAID1 data and metadata), 200 MB of test files written, restart,
  pool opens with the TPM, files intact. Then one disk removed: read-only
  degraded with the right message. Test data under 1 GB (owner rule).
- `T-INST-01` part 2 extended: the single-disk case ends with a `dup` pool.

## VERIFY

- `mkfs.btrfs` profile flags and `btrfs filesystem usage` numbers on the
  trixie btrfs-progs in the VM.
- `cryptsetup luksFormat --key-file` with a 64-byte key file and
  `--label` on cryptsetup 2.7.5.
- Mount option `degraded,ro` behaviour on kernel 6.12 with one RAID1
  member missing.

## Out of scope for this step

Scrub/balance scheduling, snapshots policy, adding a disk later, the USB
backup-disk role (rule already written: exFAT only on the installed
system).
