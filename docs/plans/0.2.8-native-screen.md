# 0.2.8 plan: the native screen (ADR 0028 #5)

Status: draft, 2026-11-24. Replaces the Chromium kiosk on the installed
system. The web console (`ui/live`) stays only for the frozen Live line.

## Shape

- New crate `crates/alp-screen` (binary `alp-screen`): GTK 4 + libadwaita
  app in Rust. Runs as the unprivileged user `alp-kiosk` under
  `cage -d -s -- /usr/lib/alp/alp-screen` (unit `alp-screen.service`,
  replaces `alp-kiosk.service`).
- It holds **no logic**: every action is a call to `alpd`, over the same
  HTTP API the web console uses (`127.0.0.1:8411/api/v1/live/...`), with
  the same console session cookie and the same rules (setup, lock, idle).
  The API contract does not change for the first version; a Unix socket
  may replace TCP later (own ADR).
- Screens, in this order of work (each maps to an existing console screen,
  same texts from `ui/live/i18n/en.json`, loaded by a small Rust i18n
  reader so the translation layer and right-to-left keep working):
  1. Lock screen and sign-in.
  2. Home (status: "All good" or the action the user must take; ADR 0023
     alert levels).
  3. Settings (Time & Language, network, phones, updates, about,
     maintenance).
  4. Setup and install (with the installer plan, `docs/plans/0.2.8-installer.md`):
     disk list (every disk; OS disks greyed with the reason), install or
     keep running from USB, passwords, pool plan.
  5. Gallery: a `webkit6::WebView` restricted to `http://127.0.0.1:8412`
     (navigation policy refuses every other origin, new-window requests,
     downloads, file dialogs, context menu and inspector; no address bar).
- Keyboard: the app handles only its own shortcuts. cage gives the app the
  whole screen; Ctrl+Alt+F2 (maintenance login) works through logind
  VT switching (fix the 0.2.7 bug where it did not: check `-s` and
  `getty@tty2` enablement).

## Scale (ADR 0028 #6)

- Lists (photos, phones, events, disks) use `gtk::ListView` with models
  filled in pages from alpd; nothing loads a whole archive.
- Long jobs show progress from alpd's job API; the screen never blocks on a
  call (all calls on a worker thread, results back on the GTK main loop).
- Test data: a generated archive of 300,000 photo records and 20 TB of
  simulated disks (sparse files) for the VM tests.

## Tests

- Unit tests: i18n loader, API client (against alpd's mock), list paging.
- VM: T-SCREEN-01 drives the app through the accessibility tree (AT-SPI;
  **VERIFY** the driver: python3-dogtail or atspi via gi, Debian versions)
  for lock, home, settings, setup; T-SEC-KIOSK-02 replaces T-SEC-KIOSK-01:
  F1, Ctrl+T, Ctrl+N, Ctrl+O, Ctrl+P, Alt+Tab, Alt+F4, F12 do nothing harmful;
  the gallery view refuses another origin; Ctrl+Alt+F2 shows the
  maintenance login; killing the app brings it back.
- Old laptops: boot the image with software rendering
  (`GSK_RENDERER=cairo`, **VERIFY** the variable for GTK 4.18) as the
  fallback when no GPU driver loads.

## Image changes

Done (2026-11-24): two mkosi profiles. `ALP_PROFILE=live` (default) is the frozen
Live image with the Chromium kiosk (`mkosi.conf.d/a-kiosk.conf` matches it).
`ALP_PROFILE=installed` (`image/mkosi.profiles/installed`) leaves Chromium out,
adds GTK 4, libadwaita and cage, ships `alp-screen` (built by
`tools/build-screen.sh`), `alp-installer` and the install layout, enables
`alp-screen.service`, and masks the kiosk and the disk protection units. CI
builds it in the VM group "installed" (T-INST-01). Still to add: WebKitGTK for
the gallery view, install-time sysupdate definitions, T-SCREEN-01.

- Add: GTK 4, libadwaita, WebKitGTK 6.0 runtime packages, AT-SPI only in
  the test profile. Remove: chromium and its policies.
- Size check against the 2 GB system image limit (spec v0.5).

## Order

1. Crate skeleton, lock + home against the alpd mock (unit tests).
2. Image: unit, cage, packages; VM test for lock/home; kiosk lockdown test.
3. Settings, then setup/install screens (with the installer work).
4. Gallery view; remove Chromium.
